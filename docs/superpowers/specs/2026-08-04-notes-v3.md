# Notes v3 — adaptive sections, reasoning tier, Terra

Ratified in conversation with Gustavo, 2026-08-04. Builds on the live-notes
removal (`dev-nova-remove-live-notes`); this branch stacks on it and merges
after it.

## The ruling

> "For the things that we have right now, you can keep them strict if you
> wanted to, but for the rest, just keep it flexible. … It's never gonna be
> strict as far as that [the template]."

Post-call notes get two natures at once:

- **The strict spine** — machine-consumed, evidence-ruled, unchanged:
  `title`, `tldr`, `conversationType`, `actionItems[]` (owner/deadline/quote,
  quote-verified, checkbox ids), `decisions[]` (quote-verified).
- **The flexible body** — `sections: [{ heading, bullets[] }]`, model-chosen
  per call. `overview`, `openQuestions`, `risks`, and `typeInsights` are
  RETIRED as fixed fields; whatever a call actually contains becomes sections
  with headings the model writes (Background / Summary / Questions /
  Discussion / Next Steps are prompt *examples*, never an enum). A short call
  earns two sections; a discovery call earns five. Q→A pairs render as
  `"…?" → answer` bullets inside a Questions section.

The one template on record (the Claire call: Action Items / Summary /
Background / Questions / Overview) is the few-shot in
`modules/notes/prompts/examples.ts` — an example of *register*, explicitly not
a mold.

## Schema (packages/shared/src/notes.ts)

- `notesContentSchema` v3: spine + `sections: z.array(z.object({ heading:
  z.string().min(1).max(60), bullets: z.array(z.string().min(1)).min(1) }))`.
  Still `.strict()` — the flexibility is INSIDE the shape, not around it.
- `meetingNotesSchema` → `version: z.literal(3)`; sections carry minted ids
  (`s1`, `s2`, …) like every other list, bullets do not (nothing diffs or
  checks off a bullet).
- Read boundary: `storedNotesSchema` accepts v1 ∪ v2 ∪ v3. v1/v2 upcast
  deterministically: `overview` → a section "Overview" (single bullet),
  `openQuestions` → "Open questions", `risks` → "Risks", sales arms →
  "Objections"/"Buying signals", interview arms → "Questions asked"/"Answers
  to revisit". Empty lists produce no section. Pure, positional, testable.
- `buildFallbackNotes` emits `sections: []` — the fallback stays the ladder's
  always-valid last rung.

## Prompt (modules/notes/prompts/)

- `system.ts`: evidence rules unchanged verbatim; add the sections contract —
  choose 2–6 headings that fit THIS call, short headings, concise bullets,
  never pad a thin call into a thick document.
- `examples.ts`: the Claire few-shot rewritten into the v3 shape.
- `map.ts`/`reduce.ts`: reduce merges sections by heading affinity; map
  contributes candidate sections. (With Terra's 1M context, classify →
  single-pass covers every realistic call; map-reduce stays as the oversize
  fallback only.)

## Model + effort (modules/llm)

- Adapter knob: `reasoningEffort` widens from `"none" | "minimal"` to
  `"none" | "minimal" | "low" | "medium" | "high"` (OpenAI-compatible
  adapter); Google adapter untouched (flash-lite has no thinking knob).
- Threading: a per-request `reasoningEffort` on the stream request (same
  pattern as `latencyTier`), defaulted OFF. The live path stays exactly as it
  is — reasoning pinned off at the adapter. The notes pipeline passes
  `reasoningEffort: "medium"`.
- Notes model: **`gpt-5.6-terra`** (verified 2026-08-04: $2/$12 per 1M after
  the July 30 cut, 1.05M context, reasoning-capable). Notes provider order
  becomes openai-first (`["openai", "google", "groq"]` — anthropic stays
  disabled/cost-vetoed). Failover to Google runs unreasoned — accepted:
  degraded notes beat no notes, and the ladder + gates catch quality floors.
- Price book: add `gpt-5.6-terra` at the verified rates. Old ids keep their
  stamped costs (append, never rewrite — the Phase 6 rule).
- `docs/BUSINESS/unit-economics.md`: new constant — worst-case notes call
  ≈ $0.10 (hour-long call, 25k in / 4k out at $2/$12); 7 hr weekly cap →
  ≈ $0.70/user/week ceiling on top of the $0.40/streamed-hr STT constant.

## Mobile

- `features/notes/notes-view.tsx` renders sections as a written page —
  heading in the mono label voice, bullets in body — replacing the fixed
  overview/openQuestions/risks/typeInsights blocks. Action items keep their
  checkbox list (ids unchanged). This is the "write it on the screen"
  instinct landing where it belongs.

## Gates (mechanical, before "done")

1. `npm run check` green all three projects.
2. Notes accuracy suite re-run LIVE on terra+medium — bar stays 5/5, plus a
   new fixture: the Claire transcript shape → asserts adaptive sections
   appear (≥3 sections, a Questions section with → pairs) and a SHORT-call
   fixture → asserts restraint (≤3 sections, no padding).
3. Upcast property tests: every stored v1/v2 fixture round-trips to valid v3
   with zero content loss.
4. Snapshot the v3 prompt (system + Claire few-shot) like the live library
   pins its prefixes.
